# Хранение данных

Решение по задаче 3.2: где хранятся данные бота и плагина и какая база данных используется.

## Что нужно хранить

- подписки на категории новостей (задача 4);
- одноразовые коды привязки и связь «игровой аккаунт ↔ Telegram» (задача 6);
- подтверждённые IP игроков для второго фактора (задача 7);
- расы и кланы, которые присылает плагин (задача 8).

## Ограничения

- **Бот и Minecraft-сервер работают на разных машинах.** Бот — на bothost.ru (Docker-контейнер, Амстердам), сервер — на отдельном хостинге Minecraft.
- **MySQL хостинга Minecraft-сервера извне недоступна.** Поддержка хостинга подтвердила: внешние подключения к базам заблокированы, порт 3306 закрыт для внешних IP, белый список и SSL-подключения извне не поддерживаются. Бот к этой базе подключиться не может.
- **На bothost сохраняется только каталог `/app/data`.** Это отдельный том, переменная `DATA_DIR=/app/data`. Всё остальное в контейнере пересоздаётся при каждом «Обновить из git» ([документация bothost](https://bothost.ru/docs/sqlite-data-lost)).
- **Своя PostgreSQL у bothost есть только на тарифе Pro**, у нас тариф «Базовый».

## Решение

1. **Данными владеет только бот.** База данных — у бота, плагин в неё не ходит.
2. **Плагин общается с ботом по HTTPS** — отправляет запросы к API бота (код привязки, вход с нового IP, расы и кланы) и получает ответы. API и его защита — задача 5.4.
3. **СУБД — SQLite**, файл `/app/data/bot.db` на постоянном томе bothost.

## Почему SQLite

- В базу пишет один процесс — бот. Для одного писателя SQLite подходит лучше всего: это один файл, без отдельного сервера, логинов и портов.
- Нагрузка маленькая: привязка — один раз на игрока, подписки меняются редко.
- Ничего не нужно настраивать на стороне хостинга и платить за отдельную базу.
- Работаем через JDBC и интерфейсы-репозитории (3.3), поэтому при необходимости SQLite можно заменить на PostgreSQL, не меняя команды.

## Какие варианты рассматривали

| Вариант | Почему не подошёл |
| --- | --- |
| Общая MySQL хостинга Minecraft-сервера для бота и плагина | Внешний доступ к ней закрыт, бот не может подключиться |
| База рядом с ботом, плагин подключается к ней напрямую | Базу пришлось бы открыть в интернет; на bothost нет базы, доступной извне |
| Плагин хранит данные в MySQL сервера и сам отдаёт их боту по HTTP | Нужен входящий порт на Minecraft-сервере; данные размазаны между двумя модулями |
| PostgreSQL от bothost | Только на тарифе Pro; для одного писателя избыточно |

## Как бот подключается к базе

- Адрес базы — переменная окружения `DB_URL` (задача 3.5). На bothost: `DB_URL=jdbc:sqlite:/app/data/bot.db`.
- Для другой СУБД достаточно поменять `DB_URL` (и задать `DB_USER`, `DB_PASSWORD`).
- Если `DB_URL` не задан, бот запускается без базы.
- Таблицы создаются при старте, если их ещё нет (задача 3.4).

## Важно

- **Файл базы — только в `/app/data`.** Путь вроде `bot.db` или `/app/bot.db` при следующем обновлении из Git даст пустую базу без всякой ошибки.
- **Файл базы не коммитить** в репозиторий.
- **Резервная копия** — скачать папку `data` через файловый менеджер в панели bothost.
